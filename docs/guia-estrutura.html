03 · Sua rotina de edição e commits

ROTINA NORMAL · layout_3d

Desenvolver o sistema atual

  1. Abra layout_3d no VS Code.
  2. Edite os arquivos da funcionalidade.
  3. Valide a mudança. Se alterou o frontend, gere o build preservando os arquivos anteriores: em projects3d/frontend, execute npm.cmd run build -- --emptyOutDir false.
  4. Em Controle do Código-Fonte, revise os arquivos e prepare-os com +. Para o frontend, inclua os fontes e o build necessário.
  5. Escreva uma mensagem sobre a mudança e clique em Commit.
  6. Clique em Push / Sincronizar para enviar ao seu GitHub.

Commit salva no computador. Push envia ao GitHub. Pull baixa alterações do repositório remoto.

SOMENTE SE EDITAR O ORIGINAL

Alterar o Visualizacao_3d separado

  1. Abra a pasta novo_input/Visualizacao_3d em outra janela.
  2. Revise, valide, faça Commit e Push nesse repositório.
  3. Volte ao layout_3d. A linha novo_input/Visualizacao_3d pode aparecer alterada.
  4. Faça commit dessa referência e envie pelo repositório principal.

Esse segundo commit registra a versão do repositório separado. Ele não copia as melhorias para projects3d/frontend/src/.

O repositório do Andrey está configurado como upstream no projeto principal; seu destino habitual de envio é origin, na conta arqlima.

04 · E nos próximos projetos?

NOVO PROJETO ARQUITETÔNICO

Outro modelo, cliente ou empreendimento

Continue usando o mesmo sistema layout_3d. Não precisa criar outro repositório para cada modelo.

  1. Prepare a pasta do empreendimento com o modelo .3dm e os dados .csv.
  2. Abra a aplicação, entre em Novo projeto e selecione a pasta preparada.
  3. Confira os arquivos, o nome e a localização; salve o cadastro.
  4. Use o visualizador. As melhorias do sistema passam a atender os projetos cadastrados.

Vídeo, capa, imagens e KMZ são opcionais conforme o cadastro. Sem KMZ, informe latitude e longitude. Alterar os dados do cadastro não exige recompilar o visualizador.

NOVO SISTEMA OU PRODUTO

Outra aplicação com evolução independente

Crie uma pasta e um repositório próprios, fora de layout_3d, quando o novo trabalho tiver código e histórico independentes.

  1. Defina se será uma continuação deste sistema ou outro produto.
  2. Se for outro produto, use uma pasta irmã, por exemplo projeto_apresentacao/novo_sistema/.
  3. Se aproveitar este sistema, parta do seu repositório principal arqlima/layout_3d.
  4. Configure o novo destino no GitHub antes de começar a enviar commits.

Evite colocar um novo repositório dentro de outro por padrão. Modelos de clientes, credenciais e banco local não devem acompanhar os commits.
